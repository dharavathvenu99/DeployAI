Integrate DeployAI with Netlify using a secure backend API.

Goal:
When the user clicks "Approve and deploy", DeployAI should deploy a prepared static website to Netlify and return the real live URL.

Important security requirements:
- Never put the Netlify token in frontend code.
- Never expose the token in browser JavaScript.
- Read the token only from the server-side environment variable NETLIFY_AUTH_TOKEN.
- Do not commit the token to GitHub.
- If NETLIFY_AUTH_TOKEN is missing, show a clear setup message instead of crashing.
- Validate uploaded files and limit the prototype to safe static deployments.
- Do not execute arbitrary user commands on the server.

Implementation:

1. Inspect the existing project and identify whether it uses React, Vite, Express, or another framework.

2. Add a backend endpoint:
POST /api/deploy/netlify

The endpoint should:
- Accept a prepared deployment ZIP file or a server-side path to a prepared ZIP file.
- Verify that the file exists and is below a reasonable size limit.
- Read process.env.NETLIFY_AUTH_TOKEN.
- Return HTTP 500 with a helpful message if the token is missing.
- Create a Netlify site using the Netlify API.
- Upload the ZIP file as a production deployment.
- Poll the deployment status until it succeeds or fails.
- Return JSON in this format:

{
  "success": true,
  "provider": "Netlify",
  "siteId": "example-site-id",
  "siteName": "deployai-demo",
  "status": "ready",
  "liveUrl": "https://example-site.netlify.app",
  "deployId": "example-deploy-id",
  "message": "Deployment completed successfully"
}

3. Add error responses in this format:

{
  "success": false,
  "provider": "Netlify",
  "status": "failed",
  "message": "Human-readable error message"
}

4. Connect the existing "Approve and deploy" button to this endpoint.

5. Update the deployment progress UI to show these real stages:
- Preparing deployment
- Creating Netlify site
- Uploading files
- Waiting for Netlify
- Running health check
- Deployment complete

6. After successful deployment:
- Display the returned live URL.
- Add an "Open live project" button.
- Add a "Copy URL" button.
- Display the provider as Netlify.
- Display the deployment status as Healthy.

7. Add a health-check endpoint:
GET /api/deploy/health?url=<liveUrl>

The endpoint should:
- Validate that the URL uses HTTPS.
- Make a server-side HTTP request with a timeout.
- Return status "healthy" only when the response is successful.
- Never request localhost, private IP addresses, or internal network addresses.

8. Preserve Demo Mode:
- If the user clicks "Try Demo", do not call Netlify.
- Complete the flow using safe sample data and a clearly labeled simulated deployment.
- Add a small label: "Demo mode: deployment simulated".

9. Add a Provider Adapter structure:
- Create a Netlify provider adapter.
- Keep the provider interface generic so Vercel or another provider can be added later.
- Use functions such as:
  - createSite()
  - deployZip()
  - getDeploymentStatus()
  - runHealthCheck()

10. Add clear user-facing error messages for:
- Missing Netlify token.
- Invalid ZIP file.
- Deployment failure.
- Timeout.
- Health-check failure.
- Netlify rate limit.

11. Update the README with:
- Required environment variable: NETLIFY_AUTH_TOKEN.
- How to create a Netlify personal access token.
- How to add the secret in Replit.
- How to run the project.
- How Demo Mode works.
- A warning never to put the token in frontend code.

Do not remove the existing mobile-first design. Keep all existing screens, navigation, sample data, and responsive styling working.
